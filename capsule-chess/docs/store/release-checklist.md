# 출시 후보 확인 — 2026-11-17

현재 판정: **로컬 출시 후보 검증 통과, 스토어 제출 보류**. JS 번들 생성은 네이티브 서명 빌드나 결제 성공을 증명하지 않는다. 기존 `CapsuleChess-1.0.0-3.aab`에는 이번 구매 기능이 없으므로 제출하지 않는다.

## 완료한 준비

- 한국어·영어, 무료 설치, 광고 없음, 전체 게임 일회성 구매 및 복원 경로 구현.
- 테스트 162개, TypeScript 검사, Android/iOS/web JS 번들 생성 통과.
- `npm run release:check`로 위 검사를 재실행하고 `release/candidate/verification.json`과 로그를 저장한다. 이 명령은 클라우드 빌드나 스토어 제출을 실행하지 않는다.
- `eas submit` 설정의 Android 대상은 내부 테스트(`internal`), 상태는 초안(`draft`). 첫 업로드는 콘솔에서 진행한다.
- 한국어·영어 스토어 설명, 상품 설명, 심사 메모, 지원·개인정보 페이지 소스 준비.
- 화면 촬영은 무료 단계 4·5를 사용하며 구매 우회 코드를 넣지 않는다. 생성한 웹 화면은 미리보기 자료이며, 최종 iPhone/iPad/Android 앱 화면을 실기기에서 다시 확인한다.

## 코드 측 출시 보류 사유

2026-11-16 npm audit 재검사: high 3, moderate 3, low 8. 촬영 도구 puppeteer-core의 허용 범위 업데이트로 high 3개를 제거한 뒤의 수치다.

- high: `expo-router → query-string → decode-uri-component`. 세 항목은 같은 디코더 의존성 경로다. 비정상 인코딩 입력에서 서비스 거부 문제가 보고됐다. 현재 SDK 57의 최신 Router는 57.0.31이며 수정판으로 제시되는 58 계열은 별도 SDK 호환성 검증이 필요하다. ESM 전용 디코더를 CJS 의존성에 강제로 덮어쓰지 않았다. SDK 업그레이드 또는 검증된 호환 패치 후 잘못된 딥링크와 정상 경로를 모두 재검증해야 한다.
- moderate: Expo fingerprint 도구의 minimatch 경로. 네이티브 런타임과 빌드 도구의 영향을 구분하고 SDK 업그레이드 때 재검사한다.
- low: Jest 도구의 deepmerge 경로. 신뢰하지 않는 Jest 설정을 실행하지 않으며, `audit fix --force`로 테스트 도구를 과거 버전으로 내리지 않는다.

## 기기 인수 테스트 기록

각 결과에 플랫폼, 모델, OS, 앱 버전/빌드 번호, 언어, 테스트 날짜를 남긴다. 비밀번호나 전체 구매 토큰은 기록하지 않는다. 아래 항목은 **현재 미실행**이다.

1. 새 설치 → 첫 캡슐 → 첫 대전 → 5단계 완료 → 6단계 구매 안내. 도장 10번은 무료, 11번은 구매 안내. 딥링크에서도 동일하게 제한.
2. 무료 사용: 레슨, 자유 대전, 매일 퍼즐. 앱 종료/재실행 후 언어와 진행 유지. 알림 권한 거절 상태에서도 게임 가능.
3. 구매 화면: 현지 가격 표시, 연결 실패 시 재시도, 취소·실패·승인 대기에서 잠금 유지. 반복 탭으로 중복 결제 요청 없음.
4. 승인 → 즉시 해제 → 재실행 → 오프라인 유료 콘텐츠 이용. Android 구매 승인(acknowledgement) 완료 확인.
5. 재설치 → 같은 스토어 계정 → 구매 복원. 다른 계정/미구매 계정에는 권한 없음. 환불·철회 후 온라인 새로고침으로 다시 잠김.
6. 공유·음향·진동·백그라운드 복귀·알림·정책 링크. Android 시스템 뒤로가기와 iPhone 안전 영역, iPad 레이아웃.
7. 초보 플레이어 5명 이상이 설명 없이 시작하고 첫 캡슐까지 플레이. 첫 수까지 시간, 첫 승리까지 시간, 실패 횟수, 구매 안내까지 시간을 관찰해 기록. 기존 봇 시뮬레이션을 사람의 플레이타임으로 간주하지 않는다.

Google 테스트 결제는 [라이선스 테스터](https://developer.android.com/google/play/billing/test)와 테스트 결제 수단을 이용한다. 테스트 트랙 참가만으로 무료 결제가 되는 것은 아니다. Apple은 [최초 구매 제출 절차](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-in-app-purchase)를 따른다.

Android는 현재 공식 Billing 클라이언트의 구매 결과로 권한을 판정하며 자체 서버 검증은 없다. 플랫폼 간 구매 이전과 기기 간 게임 진행 동기화는 제공하지 않는다.
