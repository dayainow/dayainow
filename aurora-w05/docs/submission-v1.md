# Aurora 공급 약속 검토실

AX 인재전쟁 삼일PwC W05 — 홍대의 / https://github.com/dayainow

신규 입찰을 받아도 기존 고객에게 이미 약속한 공급을 임의로 비울 수는 없습니다. 이 앱은 입찰 물량·납품일·설비 대안을 검증하고, AI 검토와 사람 승인 뒤 부서별 후속 작업까지 연결합니다. 가상 기업 데이터에 기반한 대회용 로컬 운영 데모이며 실제 수주·발주·지급·고객 통지는 없습니다.

> 초기 제출본의 기록입니다. 현재 v2 기능·검증 범위는 상위 README를 참조하세요.

## 실행

Python 3.9 이상만 있으면 기본 시연을 실행할 수 있습니다. 외부 패키지·API 키·로그인이 필요하지 않습니다.

```sh
python3 server.py --port 8765
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 서버는 loopback에만 바인딩합니다. 종료는 터미널에서 Ctrl+C입니다. 데이터는 `runtime/state.sqlite3`에 저장됩니다. 새 시연은 기존 기록을 삭제하는 대신 새 경로로 실행할 수 있습니다.

```sh
AURORA_DB=runtime/new-demo.sqlite3 python3 server.py --port 8766
python3 -m unittest discover -s tests -v
```

## 대표 실행 순서

1. **② 모의 회신 · 부분 수락**: 기초 200만 EA, 더마 120만 EA, 2026-09-01 개시, F2 전환, 5% 단가 인하. `capacity_qty`의 월간 해석과 52주 균등 공급, 기존 부하 보호, 바이어·생산·조달·품질 모의 회신을 명시합니다. 이는 실제 확인된 공급계획이 아닙니다.
2. **이 조건의 실측 AI 응답 재생**: 실제 Codex 실행 결과를 입력 해시로 검증해 불러옵니다. 새 AI 호출이 아니라고 화면에 표시합니다. AI의 조건부 제안으로 CEO 승인 대기 상태가 됩니다.
3. 승인 사유를 적고 **조건부 제안 승인 → 승인 조건으로 작업 생성**을 누릅니다. CEO/이사회 역할은 모의 처리이며 본인 인증이나 실제 결재 시스템은 없습니다.
4. 후속 작업에서 재무의 지급계획 검토가 완료되기 전에는 투자 준비 작업을 완료할 수 없습니다. 재무 **모의 완료** 뒤 종속 작업이 진행 가능으로 바뀝니다.
5. **③ 조건 변경 · 전량 요구**: 기초 600만 EA·더마 150만 EA·10% 인하로 바꾸면 기존 승인·AI 판단을 무효화하고 미완료 작업은 이전 조건으로 전환합니다. 이전 실행 영향 확인 작업과 물량·일정 재협상 작업이 생깁니다. 두 제품 모두 52주에 부족이 발생해 재승인을 할 수 없습니다.
6. **① 원본 접수 · 정보 부족**: 납품일과 능력 기간 단위, 담당자 확인이 없으면 실행을 막고 확인 작업을 만듭니다. AI 응답도 HOLD입니다. 정보 확인 작업의 완료 버튼은 사실 확인값을 자동으로 바꾸지 않습니다. 회신 후 조건을 새 버전으로 저장해야 합니다.
7. 반려는 정상 조건을 다시 불러온 뒤 AI 검토를 거쳐 **반려 · 대안 요청**으로 확인할 수 있습니다. 반려 사유를 포함한 작업이 생성됩니다.

## 실제 AI의 역할과 재현

`ai_adapter.py`는 현재 입력, 계산 결과, 원본 RFP·권한 정책·부서 메모를 Codex CLI에 전달하고 구조화된 `decision`, `summary`, `risks`, `sources`, `tasks`를 받습니다. 코드 작성 요청이 아니라 운영 시스템의 단일 검토 호출입니다. 계산은 Python이 수행하고 AI는 정보 공백·대안·후속 작업을 검토합니다. AI가 PROPOSE하더라도 수치 제약을 통과하지 못하면 승인 상태로 진행하지 않습니다.

2026-11-10 정상·변경·정보 부족 각각 한 번, 총 세 번 실제 호출을 수행했습니다. `data/ai-replays/`는 그 응답입니다. 입력 해시가 달라지면 재생할 수 없습니다. `AI 활용 기록` ZIP의 runtime 디렉터리에는 세 호출의 실제 프롬프트·응답·이벤트·실행 메타데이터가 포함됩니다. 개발 대화의 자동 훅 수집은 활성화하지 않았으며 선별한 로컬 로그를 별도로 제출합니다.

새 모델 실행은 자동 발생하지 않습니다. 본인의 Codex CLI 로그인과 사용량 승인이 필요합니다. 다음 명령은 **실제 모델 사용량을 소모**하고 자동 재시도하지 않습니다.

```sh
python3 review_once.py --scenario normal --output runtime/new-ai-review
```

새 조건은 화면의 **새 조건으로 AI 검토하기 → 검토 프롬프트 복사**를 통해 AI에 입력하고 JSON 응답을 가져옵니다. 앱이 해시·파일 근거·작업 코드·규칙을 검증합니다. 수동 가져오기는 응답의 생성자를 인증하지 않습니다. 실서비스에서는 서버 측 모델 호출과 서명된 결과·인증을 도입해야 합니다. 제품의 기본 시연은 실측 응답 재생이며 지속적인 자율 에이전트 운용을 주장하지 않습니다.

## 데이터와 가정

- 기준일은 문제 속 2026-07-01입니다. 원본 15개는 `data/original/`, 출처와 SHA-256은 `data/manifest.json`입니다. 원본 내용은 수정하지 않았습니다.
- `strat_capacity_cv.capacity_qty`의 기간 단위는 원본에 명시되지 않았습니다. 기본값은 미확인이고 판단을 보류합니다. 정상 시연의 월간 해석은 참가자 가정입니다. 연간으로 바꾸면 결론이 달라지는 테스트가 있습니다.
- 가동률 85%·97%를 52주간 유지하는 기존 부하로 보호합니다. 실제 고객별 약속·셋업·자재 달력의 재현이 아닙니다. 부족한 원본을 합성 주문으로 대체해 실제 증거처럼 주장하지 않습니다.
- 기존 부하 추가 `%p`는 스냅샷에 더하는 값입니다. 0은 기존 부하가 0이라는 뜻이 아닙니다. AI 응답의 “입력의 기존 부하 0%” 표현도 이 추가 부하를 가리키며 원본 가동률을 없애지 않습니다.
- F2 전환 12억원·7주·연 60만 EA, F1 증설 180억원·36주·연 160만 EA는 원본입니다. 설비 승인과 실제 가동 증빙은 구분합니다. 7주와 36주는 기준일에 착수한다고 가정한 가장 빠른 계획일이며 실제 발주일이 아닙니다.
- 원료 단가의 단위는 KRW/kg입니다. 2026년 4~6월 투입 kg×적용 단가를 합산하고 같은 기간 생산 EA로 나눠 제품당 자재비를 도출합니다. 원본의 로트 물량 보존 문제를 복구했다고 주장하지 않습니다.
- 1,500원/EA 추가 비용은 참가자 가정이며 편집 가능합니다. 공헌이익은 이 가정 범위의 추정치입니다. 금융비·세금·운전자금·리콜 비용은 미포함입니다. CAPEX/제안 공헌 비율은 신규 설비의 순증 효과나 실제 투자 회수기간이 아닙니다.
- USD/KRW는 2026-06-30 종가 1,478.29입니다. 단가 인하와 환율을 편집할 수 있습니다. 월 3% 페널티의 기준액은 미확인이라 전체 연매출을 기준으로 한 스트레스값만 별도 표시합니다.
- C-101 수주와 출하는 각각 order_date와 ship_date의 2026년 1~6월 집계입니다. 서로 다른 집단의 지표입니다. 발주 감소를 기존 고객 약속 취소나 이탈 원인 확정으로 해석하지 않습니다.

## 구현과 확인 범위

`engine.py`: 원본 파싱·수치 검증·52주 공급 계산. `store.py`: SQLite 트랜잭션, 버전·승인 해시·작업 의존관계·변경 이력. `server.py`: 로컬 HTTP API. `web/`: 운영 화면. `ai_adapter.py`: 구조화 모델 호출. `tests/`: 승인 우회·예외·원본 무결성·실측 AI 응답 검증.

실제 작동: 입력 검증, 계산, AI 결과 검증·반영, 승인 상태와 후속 작업 생성, 선행 작업 잠금, 변경 시 무효화, 중복 실행 방지, 영속 저장. 모의 처리: 바이어와 부서 회신, CEO 승인, 담당자 완료. 미구현: 실제 ERP/Notion/GitHub 쓰기 연동, 다중 사용자 인증, 고객별 확정 납기 최적화, 재고 예약과 실제 발주. 현재는 팀의 결정을 작업과 상태로 연결하는 작은 운영 단위에 집중했습니다.

브라우저에서 정상→승인→작업 생성→재무 의존관계→조건 변경→정보 부족을 조작했습니다. 시연 영상은 이 실제 화면 캡처를 연결한 편집본과 합성 음성 해설입니다. 연속 화면 녹화나 새 모델 호출 영상으로 표현하지 않습니다.

## 참가자의 관점

Notion에서 에픽·이슈·태스크로 팀 작업을 운영하고, Figma·GitHub·Notion을 연결한 프론트엔드 자동화와 팀 주도 경험을 반영했습니다. Claude·Codex·Gemini를 Orca와 IDE 환경에서 조합하며 하네스·스킬·멀티에이전트 작업을 다룬 경험에서, 좋은 답보다 **어느 조건의 판단인지, 누가 승인했는지, 어떤 작업이 남았는지**를 운영에 남기는 데 초점을 맞췄습니다. 경력 연차나 성과 수치는 별도로 주장하지 않습니다.
